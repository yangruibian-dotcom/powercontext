# 一页技术说明

## 1. 模块结构

```
任务描述
  │
  ├─ ctx/resolver.py ──► ctx/store.py ──► seekdb（artifacts 表）
  │                          ▲                · VECTOR(384) + HNSW
  │                          └─ ctx/indexer.py · FULLTEXT(ngram)
  │                             （specs / biz / tests 切块 + 向量化）
  │
  ├─ ctx/minimax.py ──► MiniMax（OpenAI 兼容接口）→ 返回完整文件 → 写回 biz/
  │
  └─ ctx/state.py ───► PowerContext（/v1/scopes、/v1/memory/remember、/v1/memory/search）
```

调用入口是 CLI（`ctx/cli.py`）：`index` / `resolve` / `patch` / `state` / `test`。
输入是任务的自然语言描述，输出是带真实来源的上下文（`path` + `symbol` + 两路排名）。

## 2. 上下文选择方式

1. **切块**：规格按 Markdown 二级标题切（一条 REQ 一块）；Python 按顶层函数/类切（用 `ast` 取 `lineno/end_lineno`）。
2. **编码**：本地 `all-MiniLM-L6-v2`（INT8，onnxruntime + tokenizers，384 维，L2 归一化）——不调用任何云端 API。
3. **存储**：seekdb 一张表同时建 `VECTOR(384)` + `FULLTEXT(ngram)` + `kind` 结构化字段。
4. **检索**：**一条 SQL** 里用两次 `ROW_NUMBER()` 分别算全文排名和向量排名，再按 RRF `1/(60+rank)` 融合；
   再按 `kind` 分别取 top-k，保证「规格 / 代码 / 测试」三类都进上下文。
5. **为什么分 kind 检索**：单纯整体排序时，某一类容易把名额吃光；分类型各取 top-k 才能稳定覆盖三类来源。

## 3. 技术分工

| 技术 | 在这个任务里实际承担什么 | 证据 |
|---|---|---|
| **MiniMax** | 根据上下文生成 `biz/expense/calc.py` 的修改（实现 REQ-3） | `devlog/minimax-*.md`（含上下文快照与模型回复）、`devlog/calc.py.before` 与修改后文件的 diff |
| **seekdb** | 存工程资料（20 个 chunk）并提供混合检索，检索结果直接决定上下文内容 | `python -m ctx.cli index` 输出；`resolve` 输出里的 `vec_rank/ft_rank`；`store.py` 的建表与 SQL |
| **PowerContext** | 保存任务进展（scope + memory），模块重启后读回并放进上下文 | `python -m ctx.cli state save/show`；`patch --with-state` 时上下文末尾的「任务进展」段 |

## 4. 质量与边界处理

- 返回的每个来源都能在仓库里点开对照（`path` + `symbol`），不存在编造的来源。
- 规格是索引的一部分：修改 `specs/expense-spec.md` 后重跑 `index`，`resolve` 会返回新内容（不是固定答案）。
- 目标测试与回归测试分开：目标测试验证新行为（改前失败），回归测试保护既有行为（始终通过）。
- MiniMax 调用失败（无 key / 网络 / 返回无法解析）时，CLI 会明确报错并保留上下文快照，便于排查，不会静默写坏代码。
- 写回文件前把原文件备份到 `devlog/*.before`，便于回滚与对比。

## 5. 成本与延迟（实测）

| 环节 | 耗时 |
|---|---|
| 建索引（20 chunk，含本地向量化） | < 3 s |
| 单次 `resolve`（向量化 + seekdb 混合检索） | ~0.3 s |
| MiniMax 生成一次修改 | 取决于模型（记录在 `devlog/minimax-*.md` 的 `latency_ms`） |

索引是增量的：`index --no-rebuild` 只 upsert 变化的 chunk（按 `chunk_id` 唯一键）。
