# 验证样例

> 任务：给费用报销统计的 `summarize()` 增加 `min_amount` 金额阈值过滤（见 `specs/expense-spec.md` REQ-3）。
> 判定标准：**改前目标测试失败、改后全部通过；回归测试始终通过。**

## 一、初始状态

```bash
# 1) seekdb（存工程资料）
bash scripts/start_seekdb.sh

# 2) PowerContext（存任务状态）
bash scripts/start_powercontext.sh

# 3) 模型 + 索引
python scripts/fetch_model.py
python -m ctx.cli index
# {"ok": true, "indexed": 20, "by_kind": {"spec": 6, "code": 5, "test": 9}}
```

## 二、上下文必须包含的来源（评审可逐条核对）

`python -m ctx.cli resolve --task "给 summarize 增加 min_amount 金额阈值过滤，注意边界与默认行为"` 的输出中应包含：

| 类别 | 必须出现 | 含义 |
|---|---|---|
| 规格 | `specs/expense-spec.md :: REQ-3 金额阈值筛选（本次新增）` | 本次要实现的规格条目 |
| 规格（辅助） | `specs/expense-spec.md :: REQ-2 按类别汇总` | 被扩展的既有行为 |
| 代码 | `biz/expense/calc.py :: summarize` | 需要修改的函数 |
| 测试 | `biz/tests/test_target.py :: test_min_amount_*` | 验证本次行为的测试 |

实测输出（节选）：

```
specs  : REQ-3 金额阈值筛选（本次新增） score≈0.0328 vec#1 ft#1
specs  : REQ-2 按类别汇总               score≈0.0323 vec#2 ft#2
code   : biz/expense/calc.py :: summarize  score≈0.0325 vec#1 ft#2
tests  : test_min_amount_boundary_is_inclusive  vec#1 ft#1
```

> 同样的任务，如果把 `specs/expense-spec.md` 里的 REQ-3 改掉（比如把「含边界」改成「不含边界」）再执行
> `python -m ctx.cli index`，`resolve` 输出的 REQ-3 内容会变成新版本 —— 这证明模块不是返回固定答案。

## 三、修改前：目标测试必须失败

```bash
cd biz && python -m pytest tests -q
# 5 failed, 4 passed
# FAILED tests/test_target.py::test_min_amount_filters_small_items - TypeError: summarize() got an unexpected keyword argument 'min_amount'
```

失败原因是**目标行为未实现**（`TypeError`），不是环境问题。

## 四、用 MiniMax 完成修改

```bash
export MINIMAX_API_KEY=***
python -m ctx.cli patch --task "给 summarize 增加 min_amount 金额阈值过滤，注意边界与默认行为" \
    --apply --with-state
# {"ok": true, "applied": true, "files": ["biz/expense/calc.py"]}
```

产物：

- `devlog/last_context.md` —— 实际送给 MiniMax 的上下文（含规格/代码/测试来源）
- `devlog/minimax-<ts>.md` —— 调用记录（耗时、usage、模型回复原文）
- `biz/expense/calc.py` —— 修改后的文件（原文件备份为 `devlog/calc.py.before`）

## 五、修改后：目标测试 + 回归测试全部通过

```bash
cd biz && python -m pytest tests -q
# 9 passed
```

建议保留两次 pytest 的输出（命令、退出码、当前 commit）作为证据。

## 六、任务状态保存与重启后复用

```bash
# 保存
python -m ctx.cli state save --step patch-applied \
  --text "MiniMax 已按 REQ-3 修改 calc.summarize，目标测试 5 passed"

# 模拟模块重启（CLI 每次都是新进程）后读取
python -m ctx.cli state show
# {"scope_id": "scp_...", "entries": [{"text": "[SDD-STATE][patch-applied] MiniMax 已按 REQ-3 修改 ..."}]}
```

再执行一次 `patch --with-state`，上下文末尾会出现「任务进展（PowerContext 保存的状态）」，说明状态被真正复用。

## 七、重置方法

```bash
# 清空 seekdb 里的资料索引
python - <<'PY'
from ctx import store; store.clear(); print('cleared')
PY

# 恢复业务代码到修改前
git checkout -- biz/expense/calc.py

# 清空 PowerContext 状态（可选：换一个 scope 即可）
export SDD_SCOPE=""
```
