# 验证样例

> 下面的实测输出是在本机真跑出来的（seekdb 嵌入式实例 + 本地 all-MiniLM-L6-v2 INT8）。

## 一、初始状态

- 依赖已安装：`npm install`
- 模型已下载：`npm run fetch-model`（`models/all-MiniLM-L6-v2/`，q8 约 21.91 MB）
- 执行 `npm start`，控制台出现 `科研资料混检助手 → http://localhost:5273`
- 浏览器打开后，顶部状态栏显示 `seekdb：0 条资料 · 384 维`

## 二、样例 1：导入并检索（核心流程）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 点「载入示例资料（20 条）」 | 日志显示 `已准备 20 条资料` |
| 2 | 点「向量化并写入 seekdb」 | 日志出现 `向量化 ~220 ms · 写库 ~70 ms · 共 20 条` |
| 3 | 输入 `中文全文检索为什么搜不到`，模式「混合」，点检索 | 第一条是《中文全文检索的分词问题》，meta 里同时有 `全文#1` 和 `向量#1` |

**技术发挥作用的证据**：结果里的 `全文#n` / `向量#n` 就是 seekdb 内部两路召回的排名；如果只用向量，这条会掉到后面甚至召不回（见样例 3）。

## 三、样例 2：标签过滤（结构化条件）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 输入 `检索`，标签填 `检索` | 结果只剩 tags 含「检索」的资料（如《HNSW》《SQL 标量过滤与索引》） |
| 2 | 同样的查询，标签留空 | 结果范围变大，会出现不带该标签的资料 |

**证据**：查询日志里 `tags` 字段为 `检索`，返回条数明显少于空标签时。

## 四、样例 3：三种模式对比（说明为什么需要混合）

同一句 `向量索引 HNSW 原理` 下：

| 模式 | 典型结果 |
|---|---|
| 仅向量 | 语义相近的几条（可能出现"SQL 标量过滤"这类相邻话题） |
| 仅全文 | 精确命中 "HNSW" 的《向量索引 HNSW 原理》，但召不回同义表述 |
| 混合 | 两条优点都在：精确命中排前，同义表述也能带上 |

## 五、实测输出（`npm run verify`）

```
model loaded in 159ms (all-MiniLM-L6-v2)
向量化 20 条：223 ms（89.7 条/秒）
seekdb ready in 3115ms (tcp, ...\qoder\data\seekdb)
写库：73 ms（total=20）

模式       | Recall@5 | 查询向量化(中位) | seekdb 检索(中位)
-----------|----------|------------------|------------------
hybrid     |    1.000 |              3 ms |             11 ms
vector     |    0.800 |              3 ms |              1 ms
fulltext   |    1.000 |              3 ms |              2 ms
```

**怎么读**：`vector` 那条只召回 80%，说明 10 条评测查询里有 2 条纯靠向量召不回目标资料；
`hybrid` 把这两条补回来了 —— 这就是"混合检索在 seekdb 里做"的实际价值。

## 六、HTTP 接口实测（curl）

```bash
# 导入
curl -s -X POST http://127.0.0.1:5273/api/import-text \
  -H 'Content-Type: application/json' \
  -d "$(node -e 'process.stdout.write(JSON.stringify({docs:JSON.parse(require("fs").readFileSync("data/corpus.json","utf8"))}))')"
# {"ok":true,"embed_ms":233,"inserted":20,"total":20,"write_ms":108}

# 检索
curl -s -X POST http://127.0.0.1:5273/api/search \
  -H 'Content-Type: application/json' \
  -d '{"queryText":"全文检索","mode":"hybrid","k":3}'
# rows: p03(ft1/vec1), p14(ft5/vec3), p16(ft4/vec5)
```

## 七、注意事项（复现时容易踩）

`data/seekdb` 是嵌入式实例的数据目录，**同一时间只能被一个进程打开**。
如果一边跑 `npm run verify` 一边跑 `npm start`，会出现"刚导入却搜不到"的假象 —— 这是两个实例抢目录，不是检索逻辑问题。复现时先停掉另一个进程。
