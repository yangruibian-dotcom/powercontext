科研资料混检助手

论文摘要、课程笔记、实验记录都扔进来。一句自然语言问题，直接定位到相关段落，并告诉你出处在哪一页、哪一段。

Qoder 开发 seekdb 向量 + 全文 + 标签混合检索 本地向量化，无云端 API Node.js · 单条 SQL 完成融合

解决的问题

「明明写过，就是翻不到」

资料散在下载文件夹、笔记 App 和实验记录表里，关键词想不起来就等于丢失。

关键词搜不到同义表述

「融合策略」和「怎么把两路结果合起来」是同一个意思，纯关键词检索永远搜不到。

纯语义检索会漏掉术语

「HNSW」「nDCG」这类专有名词，语义模型容易和相邻话题混淆，需要精确匹配兜底。

所以这个工具同时跑两路召回：全文负责精确术语，向量负责同义改写，再用标签把范围收窄， 最后在数据库里用 RRF 融合排序。

核心功能

批量导入

示例资料一键载入，或直接粘贴自己的文本；空行分段，首行当标题。

本地向量化

all-MiniLM-L6-v2（384 维，INT8）在本机 CPU 运行，资料不出本机。

混合检索

一条 SQL 内完成两路召回 + RRF 融合，不用把结果拉回应用层拼。

标签过滤

先用结构化条件缩小候选集，再做排序，避免过滤后结果不足。

出处定位

每条结果带有 source 字段（论文 · 章节 / 笔记日期），点回原文位置。

可解释排序

显示「全文#n」「向量#n」两路各自排名，能看出它为什么被排上来。

检索流程

你的问题→本地向量化→ seekdb：全文召回+seekdb：向量召回→ RRF 融合排序→带出处的结果

技术栈

seekdb（核心）

嵌入式启动，一张表同时建 VECTOR(384)、FULLTEXT(ngram) 与普通列，混合检索用一条 SQL 完成。

Node.js

零框架 HTTP 服务 + 静态页面；@oceanbase/seekdb-node 管理嵌入式实例，mysql2 走 MySQL 协议。

Transformers.js

在 Node 侧本地加载 all-MiniLM-L6-v2 INT8，做批量向量化，不访问任何云端推理接口。
